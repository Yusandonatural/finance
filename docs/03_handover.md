## 2. 会社・会計の前提知識

- 株式会社悠三堂。奈良の自然栽培茶（製茶・小売・EC・海外・卸）。freee 上は **農業・製造業テンプレート**（製造原価報告書あり）。
- **決算期 3月1日〜翌2月末日**。freee API の `fiscal_year` は **期首の年**（2026 = 2026/3〜2027/2）。
- **棚卸は期末のみ**。期中は freee 上、期首棚卸が全額費用化され期末棚卸が 0。このアプリの存在理由。
- 棚卸資産は 製品・仕掛品（荒茶）・原材料 の3区分。商品勘定は未使用。
- 売上区分は勘定科目で分かれている（小売売上高 / 売上高 / 海外売上高 / EC売上高）。部門（sections）はセグメントとして使えない。
- 減価償却費は決算時に年1回計上（前期 394,604）。
- 純資産はマイナス（債務超過）だが役員借入金が約1,300万円ある。銀行提出では役員借入金の明細を必ず付ける。

## 4. 設計上の決定事項と理由（要点）

| 決定 | 理由 |
|---|---|
| Cloudflare Workers + Hono + D1 + R2 | 既存アプリと同じ基盤で運用負荷を増やさない。無料枠で収まる |
| freee は読み取り専用。補正は freee に書き戻さない | 会計帳簿を汚さない。税理士の処理と衝突しない |
| 補正は「freee 値 / 補正 / 補正後」を常に並記し、注記に方法と金額を自動出力 | 銀行・税理士への説明可能性。粉飾と誤解されないため |
| 補正方法は B 前期末据置法を採用（期首棚卸高をそのまま月末棚卸高とみなす）。A 実地簡易入力は任意の上書き、C 原価率法は参考 | 依頼者決定（2026-09-27）。入力不要で毎月確実に出せる。B と C の差（2026/8 で約240万円）は感応度表で開示 |
| 比較年度（前期同期・前々期同期）にも据置法を適用 | 前年同期比を同じ基準で並べるため |
| 月次推移には補正を按分しない（累計にのみ適用） | 月按分の根拠が弱い。注記で明示 |
| PDF は初版「印刷CSS + ブラウザで保存」 | 実装コストゼロで確実。サーバ生成は Phase 2 |
| 3期比較は freee `*_three_years` API を使う | 同一期間累計の前期・前々期を1回で取れる |
| 決算確定年度の応答は D1 に永続キャッシュ | 変わらないデータを毎回取らない |

## 4.5 画面デザイン（2026-09-28）

- 配色：紙の白（`--bg #f6f5f0`）と茶葉の緑（`--accent #237a4f`）。ライト／ダークの両方を `public/app.css` の CSS 変数で定義。
- グラフは `src/views/charts.ts` がサーバー側で SVG を描く（外部ライブラリなし）。ホバー時の数値表示は `public/app.js`。
- グラフの系列色（当期＝緑、前期＝琥珀）は色覚シミュレーションで判別できることを検証済み。light `#237a4f / #d09a45`、dark `#1a7a48 / #bf8a2a`。変えるときは再検証すること。
- フォントは Google Fonts（Noto Sans JP、見出しに Noto Serif JP / Shippori Mincho）。読めない環境では OS のフォントで表示される。
- 提出用ページは表紙＋8セクションで A4 9ページ。ページ番号とヘッダーは `@page` の余白ボックスで出す（Chrome 131 以降）。月次推移は A4 横。
- 注意：印刷時、flex / grid で並べた SVG は Chrome が次ページへ送ることがあるため、`.chart-row` は inline-block で並べている。

## 5. 既知の課題・注意点

- **yusando.com の DNS の所在を未確認**（開発環境から DNS 照会ができなかった）。Cloudflare にあれば `finance.yusando.com` をそのまま使える。Route 53 のままなら README の B 案（workers.dev + Access）。
- freee 実 API での取込は、OAuth 登録前のため未確認。応答の正規化（`src/freee/client.ts` の `fetchReport`）は freee MCP で取得した実応答の形に合わせてある。
- 月次推移の単月データは、テスト用フィクスチャでは主要な合計行だけを持つ。実取込では全行が入る。

1. **B/S 棚卸資産の残置額 931,966 円**（製品 63,967 / 原材料 96,415 / 仕掛品 771,584）。期首振替で戻らず常に残る。前期末 B/S 棚卸資産 6,115,955 と P/L 期末棚卸 5,183,989 の差に一致。税理士確認待ち。帳票では「残置額」として別建て。
2. freee `trial_*` API は `start_month`〜`end_month` で年度をまたげない。3〜2月は同一年度内として指定できる（例: `fiscal_year=2025, start_month=3, end_month=2`）。
3. `display_type=group` 以外で `breakdown_display_type` を指定すると 400。
4. `up_to_date=false` の応答は集計未完了。確定操作は止めること。
5. `account_items` は 308 件。API 応答が大きい（約 230KB）。マスタは D1 にキャッシュする。
6. freee MCP のトークン期限切れ表示は自動更新されるので気にしなくてよい（本セッションで確認）。
7. freee 申告API（`/hub/tax_return/*`）は本連携では使えない。過去決算書PDFはAPIで取れない。

## 9. 用語

| 用語 | 意味 |
|---|---|
| 試算表 | 残高試算表。月末時点の B/S・P/L。銀行提出の基本資料 |
| CR | 製造原価報告書（freee `trial_cr`）。材料費・労務費・製造経費 → 当期製品製造原価 |
| 期首/期末棚卸振替 | 在庫を費用⇄資産に振り替える決算仕訳。freee は期首に自動、期末は決算時 |
| 据置法 | 期中の在庫を期首棚卸高（= 前期末の在庫額）で据え置く見積方法。本アプリの採用方法 |
| 原価率法 | 売上に前期原価率を掛けて売上原価を推定し、差引で在庫を見積る方法 |
| ブリッジ | freee 純損益から補正後純損益までの増減内訳表 |
| `up_to_date` | freee 試算表 API の集計完了フラグ |
