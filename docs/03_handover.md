## 2. 会社・会計の前提知識

- 株式会社悠三堂。奈良の自然栽培茶（製茶・小売・EC・海外・卸）。freee 上は **農業・製造業テンプレート**（製造原価報告書あり）。

- 純資産はマイナス（債務超過）だが役員借入金が約1,300万円ある。銀行提出では役員借入金の明細を必ず付ける。

## 4. 設計上の決定事項と理由（要点）

| 決定 | 理由 |
|---|---|
| Cloudflare Workers + Hono + D1 + R2 | 既存アプリと同じ基盤で運用負荷を増やさない。無料枠で収まる |
| freee は読み取り専用。補正は freee に書き戻さない | 会計帳簿を汚さない。税理士の処理と衝突しない |
| 補正は「freee 値 / 補正 / 補正後」を常に並記し、注記に方法と金額を自動出力 | 銀行・税理士への説明可能性。粉飾と誤解されないため |
| 補正方法は B 前期末据置法を採用（期首棚卸高をそのまま月末棚卸高とみなす）。A 実地簡易入力は任意の上書き、C 原価率法は参考 | 依頼者決定（2026-09-27）。入力不要で毎月確実に出せる。B と C の差（2026/8 で約240万円）は感応度表で開示 |
| 比較年度（前期同期・前々期同期）にも据置法を適用 | 前年同期比を同じ基準で並べるため |
| 月次推移には補正を按分しない（累計にのみ適用） | 月按分の根拠が弱い。注記で明示 |
| PDF は初版「印刷CSS + ブラウザで保存」 | 実装コストゼロで確実。サーバ生成は Phase 2 |
| 3期比較は freee `*_three_years` API を使う | 同一期間累計の前期・前々期を1回で取れる |
| 決算確定年度の応答は D1 に永続キャッシュ | 変わらないデータを毎回取らない |

## 4.6 今期の目標（2026-11-05）

- 画面 `/targets`（`src/views/targets.tsx`）。計算は `src/report/targets.ts`、テストは `test/targets.test.ts`。D1 は `migrations/0002_targets.sql`（`targets`・`target_notes`、本番に適用済み）。
- 入力するのは売上の勘定科目ごと・売上原価・販売管理費・営業外収益・営業外費用の年額。売上総利益・営業利益・経常利益は自動計算。
- 「目安」＝ 今期目標 × 前期の同じ時期までに通期の何割だったか。季節の偏りが大きいため単純な月割はしない。当期実績・前期同期は棚卸補正後、前期実績は決算確定値。
- 状況の判定：目安との差が 0 以上で「目安以上（費用は以内）」、差が目安の10%以内で「やや」、それ以上で「下回る／超過」。利益の行は前期が0円近くになりやすいので、前期比を率でなく差額で出す。
- 同じ画面の下から今期の施策を追加できる（`/initiatives` に `return=targets` で POST）。「効く目標」は施策の関連科目として保存される。
- まだ提出用ページには目標を載せていない（予算実績の比較表を加えるのが次の候補）。

## 4.7 claude.ai 版（2026-11-05、現在の本番）

- 依頼者の判断で、Cloudflare への公開はやめて claude.ai のアーティファクトとして動かす。アーティファクト「悠三堂 試算表」（claude.ai/artifact/RNc4Nv2DDjUdLvztDZwn8G、非公開）。
- 仕組み：`src/client/main.ts` が Hono アプリ（`src/index.tsx`）をブラウザ内で `app.fetch` し、リンクとフォーム送信を横取りして画面を差し替える。サーバー版のルート・画面・計算はそのまま共用。
- 保存先：`src/db.ts` の各関数は `env.DOCS` があると `src/store/docs.ts`（アーティファクトの db）へ処理を渡す。文書の配置は docs.ts の冒頭コメント。1文書 256KB まで（実測の最大は約 30KB）。
- freee：`src/freee/client.ts` が `env.FREEE_MCP` のとき freee コネクタの `freee_api_get` を呼ぶ。コネクタのエラーは対処の文に変えて取込画面に出す。
- 添付：アーティファクトの assets（PDF・画像・CSV のみ。Excel・Word は PDF にしてから）。
- 提出用：`/print` の HTML に print.css を埋め込み、downloads でファイル保存。ブラウザで開いて印刷 → PDF（A4 9ページを確認済み）。
- 確認画面：claude.ai では `confirm()` が使えないため、`data-confirm` 属性のフォームは独自の確認画面を出す（Workers 版は従来どおり `confirm()`）。
- ないもの：毎月5日の自動取込（取込画面のボタンで行う）、Cloudflare Access（アーティファクトの共有設定がアクセス制御）。
- テスト：`npm run check`（型チェック2種＋vitest）。claude.ai 版は、db・freee を模したスタブで取込→目標→施策→添付→削除→確定→提出ファイル保存→棚卸補正を通しで確認した（2026-11-05、13 手順すべて成功）。

## 4.8 入力の保持と、提出用の「今期の目標」（2026-11-05）

- 「記入した内容が消える」報告への対応。調べると、freee の取込は成功していたが、目標・施策・棚卸補正は1件も保存されていなかった（保存前の入力が、同じ画面の別フォームの送信や画面の読み込み直しで消えていた）。
- `src/client/main.ts`：保存前の入力を「下書き」として sessionStorage に保管し、描き直し・移動・読み込み直しの後に戻す。保存に失敗して同じ画面に戻ったときも送信した入力を戻す。保存に成功したフォームの下書きは消す。保存前の変更があるフォームには「未保存の変更があります」を表示。
- 保存の成否は、レイアウトのお知らせに付けた `data-flash="ok|error"` で判定する（画面内の注意書きも `flash error` の見た目を使っているため、クラスでは判定しない）。
- エラーの記録：画面の処理で起きたエラーは db の `meta/errors`（直近 50 件）、サーバー側のエラーは操作履歴（`meta/audit`、action=error）に残す。不具合の報告があれば ArtifactData でこの2つを読む。
- 提出用ページに「今期の目標」を追加（目標か考え方が入っているときだけ）。前期実績・今期目標・前期比・その月までの実績と目安・進捗・状況の表と、「目標の考え方」の本文。進み具合は、その試算表と同じ月までの実績で出す。A4 10ページ。

## 4.9 過去の決算と5期推移（2026-11-05）

- 画面 `/closings`（`src/views/closings.tsx`）。「過去の決算をすべて取り込む」で、freee にある過去の全期（進行中の今期を除く。2016年度〜）の通期 P/L・製造原価・B/S を取り込む（`syncAllClosings`、1期 3回。取込済みは飛ばし、印を付けると取り直す）。
- 決算の要約は `src/report/closings.ts` の `closingSummary`。claude.ai 版は取込時に `closings/<fy>` へ要約を保存し、画面はそれだけを読む（通期データ 30 文書・約 600KB を毎回読まないため）。要約がなく通期データだけある場合は、初回に作る。
- 設立初年度（2016-10-03〜2017-02-28、5ヶ月）のため、期末月は freee の終了日から取る（`endMonthOf`）。12ヶ月未満の期は表で「5ヶ月」と示し、年平均伸び率の計算から外す。
- 過去5期の比較（`fiveYearCompare`）：売上高と区分ごとの内訳、売上総利益、粗利率、販管費、営業・経常・当期純利益、純資産、借入金、役員借入金。前年比と5期の増減、売上高の年平均伸び率。
- 決算書の PDF は添付の `category='closing'`・`fy=その年度` で保存し、施策・添付の画面には出さない。Workers 版の D1 は `migrations/0003_attachment_category.sql` が必要（本番 D1 には未適用。Workers 版を使うときに適用する）。
- 提出用資料の「過去の決算」に、5期の推移グラフ・比較表・全期の一覧・登録した決算書の名前（別添）を載せる。A4 1ページに収まることを確認。
- 比べる期数は 3・5・10 から選べる（`/closings/years`、設定は meta の `compare_years`、既定 5）。提出用資料の推移と比較表も同じ期数。10期でも A4 1ページ（表は小さめの文字）。
- 年平均伸び率は12ヶ月そろった期だけで計算する（範囲に設立初年度が入っても、2017年度からで計算）。12ヶ月に満たない期を基準にした前年比は表示しない。

## 4.10 「freee から取り込みができない」への対応（2026-11-05）

- 記録（`meta/errors`・`meta/audit`）では、「過去の決算をすべて取り込む」が2回とも「Failed to fetch」で止まり、`syncAllClosings` は一度も走っていなかった。エラーは取込処理の外側、送信内容の読み取り（`parseBody`）で起きていた。このフォームは「取り直す」の印を付けないと送信内容が空になり、claude.ai の画面内では空の送信内容の読み戻しが失敗するとみられる（手元の Chromium では再現しない）。月の取込・目標の保存（項目のあるフォーム）は成功していた。
- 対応：`src/client/main.ts` で送信内容を空にしない（`_sent=1` を足す）。ファイルを含まないフォームは URL エンコード形式で送る。`src/index.tsx` の送信内容の読み取りを `readBody` に集め、読めないときは原因がわかる文で止める（過去の決算の取込だけは、読めなくても通常の取込として進める）。

## 4.11 製造業向け機能を使っていない期（2026-11-05）

- 2016〜2019 年度は freee の「製造業向け機能（業種別テンプレート）」がオフ。製造原価報告書（`trial_cr`）を求めると 400「製造業向け機能を使用しない設定になっています」が返る。
- `src/sync.ts` の `fetchReportOrEmpty` が、このエラーのときだけ空の製造原価報告書（`balances: []`）を保存して取込を続ける。損益計算書・貸借対照表はふだんどおり取る。ほかのエラーはそのまま失敗として扱う。
- freee のエラー文は `freeeDetail` で「エラー詳細」の部分だけを表示する（決まり文句のヒントは省く）。

## 4.12 売れ筋商品（Shopify、2026-11-05）

- 画面 `/products`。Shopify コネクタの `run-analytics-query`（ShopifyQL）で、会計年度（3月〜2月）ごとに商品別の純売上と販売数を取る。
  - 問い合わせ：`FROM sales SHOW net_sales, quantity_ordered GROUP BY product_title SINCE <期首> UNTIL <期末 or 今日> ORDER BY net_sales DESC LIMIT 1000`
  - 保存先：claude.ai 版は `products/<fy>`、D1 版は `app_meta` の `products:<fy>`（Workers 版には Shopify の接続がないので、取込は claude.ai 版だけ）。
  - 終わった年度は一度だけ取り込み（「取り直す」で再取得）、今期は毎回取り直す。
- 順位は直近の終わった年度で決める。上位 5/10/20 商品、売上／販売数、3/5/10 期を切り替えられる。期数は「過去の決算」と共通（`compare_years`）。
- 商品名が空の行は「商品登録のない売上」としてまとめる。2026年度は主に下書き注文（Draft Orders）の手入力の商品。
- 提出用資料には、終わった年度だけで上位10商品の売上を載せる（取り込んでいなければ載せない）。
- 注意：Shopify の純売上は税抜で、送料・税を含まない（freee の売上高とは一致しない）。商品名は現在の名前で集計される（例：「悠三堂の福袋2026」が2024年度にも出る）。

## 5. 既知の課題・注意点

- **yusando.com の DNS は Route 53**（2026-11-05、`wrangler deploy` が「Could not find zone for finance.yusando.com」で確定）。そのため workers.dev で公開する設定に変更済み。`APP_ORIGIN` は空にしてあり、freee のコールバック URL はアクセスされたアドレスから組み立てる。
- freee 実 API での取込は、OAuth 登録前のため未確認。応答の正規化（`src/freee/client.ts` の `fetchReport`）は freee MCP で取得した実応答の形に合わせてある。
- 月次推移の単月データは、テスト用フィクスチャでは主要な合計行だけを持つ。実取込では全行が入る。

1. **B/S 棚卸資産の残置額 931,966 円**（製品 63,967 / 原材料 96,415 / 仕掛品 771,584）。期首振替で戻らず常に残る。前期末 B/S 棚卸資産 6,115,955 と P/L 期末棚卸 5,183,989 の差に一致。税理士確認待ち。帳票では「残置額」として別建て。
2. freee `trial_*` API は `start_month`〜`end_month` で年度をまたげない。3〜2月は同一年度内として指定できる（例: `fiscal_year=2025, start_month=3, end_month=2`）。
3. `display_type=group` 以外で `breakdown_display_type` を指定すると 400。
4. `up_to_date=false` の応答は集計未完了。確定操作は止めること。
5. `account_items` は 308 件。API 応答が大きい（約 230KB）。マスタは D1 にキャッシュする。
6. freee MCP のトークン期限切れ表示は自動更新されるので気にしなくてよい（本セッションで確認）。
7. freee 申告API（`/hub/tax_return/*`）は本連携では使えない。過去決算書PDFはAPIで取れない。
