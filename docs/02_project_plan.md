## 5. 各フェーズの作業分解（開発）

### Phase 0
1. `wrangler init` 相当の雛形、Hono ルーティング、Vite + Preact、D1 migration 0001（§6 のDDL）
2. freee OAuth（start / callback / refresh、D1 暗号化保存）
3. `GET /api/periods`（companies → fiscal_years）
4. CI（型チェック・テスト）と `README.md` のローカル起動手順

### Phase 1
1. freee クライアントと mappers（応答 → 内部行モデル、階層・合計行の扱い）
2. `POST /api/sync`（スナップショット保存、確定年度キャッシュ、`up_to_date` 保持）
3. `report/inventory.ts` 補正 B（当期・前期・前々期に適用）、`report/checks.ts` 検算
4. `report/assemble.ts`（bs / pl / cr / monthly / bridge / past_fy）
5. 画面: ダッシュボード、取込、棚卸補正
6. 印刷HTML（表紙・B/S・P/L・CR・月次推移・ブリッジ）
7. テスト: 付録A 実測値フィクスチャ、境界（E_k=0、上限超過、年度またぎ指定エラー）

### Phase 2
1. 施策 CRUD、添付アップロード（R2）、年度共通添付
2. 借入金明細、実質純資産の参考値
3. 減価償却月割、補正A（実地簡易入力・単価マスタ）、補正C（原価率法）、感応度表
4. パッケージ確定（report_json 凍結、版管理）、提出履歴画面
5. 添付PDF結合（pdf-lib を Workers で実行。無理なら Browser Rendering）
6. 注記文テンプレ（作成基準）の整備、税理士レビュー反映

### Phase 3
1. Cron（毎月5日）で前月分取込、`up_to_date=false` の警告表示
2. 資金繰り表（現預金推移 + 返済予定 + 見込入力）
3. D1 export → R2 バックアップ（GitHub Actions 月次）
4. 銀行フィードバック反映

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 据置法の見積が実態と乖離していると銀行・税理士に問われる | 提出物の信頼性 | 注記で「期首棚卸高を据え置き」と方法・金額を明示。感応度表（A/B/C）を添付。求められた月は A で上書き |
| freee 側の集計遅延（`up_to_date=false`） | 数値がずれる | 警告表示、確定操作をブロック、再取込ボタン |
| freee リフレッシュトークンの失効（未使用期間や並行更新） | 取込不能 | 取込前に必ず refresh、失敗時は再認可導線。Cron で月1回は必ず使う |
| 勘定科目の追加・改名 | 行マッピングのずれ | カテゴリ名とIDの両方で判定。未知科目は「その他」に集約し警告 |
| 添付PDF結合が Workers の CPU 制限に触れる | PDF出力失敗 | 初版は結合せず個別ファイルとして同梱。Phase 2 で Browser Rendering |
| 代表の入力負担（単価・施策） | 運用が止まる | 単価は年1回、施策は追記のみ。据置法で最低限の帳票は出る設計 |
